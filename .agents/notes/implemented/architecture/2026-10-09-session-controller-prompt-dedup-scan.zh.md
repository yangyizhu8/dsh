# Agent Note：重试的提示请求去重不再复制整份日志

Status: implemented

[English](2026-10-09-session-controller-prompt-dedup-scan.md) | 中文

## 问题

`api/session-controller` 的 `hasPromptRequest` 判断传入的提示 RPC 请求 id 是否已被记录，从而让重试被确认而不是被追加两次。在内存收件箱检查之后，它退回使用 `agent.session.snapshotEvents().some(...)`。

这条退路在长会话上要付两次代价：快照在搜索开始前就复制了整份事件数组，而正序扫描从最旧的事件开始——重试请求的原件就在近尾，却要走过整份日志才找到。本部署的活会话最多持有 160 万条事件，因此一次重试可能复制并扫描数百万条事件。

## 决定

该退路改为经 `eventAt` 点读**由新到旧**扫描，命中即停。不分配任何数组，而常见情形——原件刚被追加不久的重试——只需寥寥数次读取即可判定。

收件箱检查仍在最前，因此尚未提交的请求无需触碰日志即可识别。

## 备选方案

`snapshotEvents().toReversed().some(...)`：**否决**。反转会在扫描前复制整份数组，既保留了分配又多加一次。

读持久日志：**否决**。原件尚未落盘时会被漏判，请求将被二次追加。

把扫描限制在近期窗口：**否决**。它会静默地不再发现更早的重复，把成本问题换成正确性问题。

## 影响

- 该退路不分配任何东西，且命中前每步最多读一条事件。
- 检测仍覆盖整份日志，因此更早的重复依旧能被发现；改变的只是扫描顺序。
- 这次读取保留其既有的 `typescript/no-deprecated` 豁免：它是同步历史读，迁移已延期。
